# 古法纸浆发酵记录

运行：

```bash
npm start
```

访问 `http://localhost:3039`。数据保存在 `data/paper-pulp-fermentation.json`（可用环境变量 `PULP_DB_PATH` 指定其他路径，便于测试）。

## 模块划分

- `server.js` — 请求入口：HTTP 路由、请求体解析、状态码与错误报文。
- `src/rules.js` — 状态规则：缸位排他、观察必填校验、异常复核闭环、状态流转、列表摘要与统计口径。
- `src/store.js` — 记录存储：JSON 文件的读取/写回，所有写操作经单次“读取-修改-保存”完成。
- `src/page.js` — 页面视图：列表、统计与表单全部取自接口，刷新后与后端一致。

## 业务规则

- **缸位排他**：每口缸同时只能有一批在缸（入缸、发酵中、异常观察均占缸；可抄纸后缸位释放）。同缸重复建档返回 `409 vat_occupied`，冲突数据不落库。
- **每日观察必填**：温度、气味、纤维松散度、换水缺一不可（另需观察人），缺项返回 `400 missing_fields`，记录不保存。
- **异常复核闭环**：观察到异味或霉点只能转入“异常观察”并生成待复核案件；须由**另一人**填写复核人与处置（同一人复核返回 409）。复核后连续 **2 次正常且完成换水**（中途缺换水则计数清零）才恢复发酵；待复核期间不能提交正常观察。
- **可抄纸进度**：累计发酵满 7 天转为“可抄纸”；异常观察（含待复核）批次不计入可抄纸进度，进度接口同时返回待复核批次数与在缸缸位。
- 状态只能由观察/复核流程驱动，接口拒绝手动修改状态或缸位。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items` | 批次列表（含观察数、待复核标记） |
| GET | `/api/stats` | 状态计数、可抄纸进度、待复核数、在缸缸位 |
| POST | `/api/items` | 建档（缸位冲突 409） |
| POST | `/api/items/:id/observations` | 每日观察（缺项 400；异常自动转异常观察） |
| POST | `/api/items/:id/review` | 异常复核（复核人须不同于上报人） |
| POST | `/api/items/:id/logs` | 追加备注 |
| PATCH | `/api/items/:id` | 仅允许修改原料来源、负责人 |
